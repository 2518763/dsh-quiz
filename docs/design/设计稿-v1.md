## 0. 一句話定義

把「出題 → 作答 → 批改 → 錯題回爐」做成 DSH 側邊欄裡的一塊，題目**一律由本地資料庫裡的資料出**，找不到出處就不出題。

---

## 1. 三條硬規則

1. **無出處不出題**：每題必須綁定 `chunk_id`（一段原文＋頁號），資庫裡沒有就跳過並明示「未覆蓋」。
2. **答案以資料為準**：給分要點從原文抽取或直接抄 marking scheme，批改時可點開看原文，不靠模型印象。
3. **長答不自動批改**：插件只計時、存作答全文、等我把分數回填。

---

## 2. 資料來源與入庫

### 2.1 允許的資料類型

| 類型 | 例子 | 入庫方式 |
|---|---|---|
| 課本 | 中四經濟課本 | PDF 抽字／拍照 |
| 筆記 | 手寫或課堂筆記 | 拍照 → 我轉文字 |
| 練習/工作紙 | 老師派的題 | 拍照 → 我轉文字 |
| 真題 | DSE 歷年 Paper 1 / Paper 2 | 拍照或 PDF ＋ 官方 marking scheme |

### 2.2 入庫流程（已確認可接受）

1. 用戶發圖或發檔案給我
2. 我整理成結構化文本（保留章節標題、頁號、題號）
3. 存進 `sources/<book-slug>/chNN.md`
4. 建 chunk 索引

### 2.3 目錄結構

```
dsh-quiz/
  sources/
    econ-longman-s4/          # 一本資料一個目錄
      ch01.md
      ch02.md
    dse-econ-2019/
      p1.md
      p2.md
      ms.md                   # marking scheme
  data/
    sources.json
    questions.json
    attempts.json
    schedule.json
```

### 2.4 檔案格式（frontmatter ＋ 按小節切段）

```markdown
---
book: 經濟學 中四上
type: textbook
pages: 12-34
---

## 1.1 稀少性與選擇（p.12）

原文……

## 1.2 機會成本（p.18）

原文……
```

**切段規則：按小節（## 標題）切，不按字數切。** 保住前後文，避免出斷章取義的題。

---

## 3. 資料模型（最終進 SQLite，v1 先用 JSON）

```
sources     id, book, type, pages, added_at
chunks      id, source_id, heading, page, text
topics      id, name, aliases[]
questions   id, type, topic_id, chunk_id, stem, options[], answer_points[], level, created_at, seen
attempts    id, question_id, answer, verdict, score, seconds, at
schedule    id, question_id|topic_id, stage(1/2/3), due_at, streak_ok
```

`questions.chunk_id` **不可為空**，這是防亂匹配的數據層防線。

---

## 4. 出題流水線

1. 選範圍（見 §7）
2. 每個 topic 撈 1–2 段相關 `chunks`
3. **有料才出題**：無對應段落 → 跳過，結果頁標示
4. 生成題目：題型、題幹、選項、要點、解析；要點要能對回原文句子
5. 存庫：帶 `chunk_id`、頁號、生成日期

結果頁一定要顯示：

> 本次跳過：邊際分析（資料未覆蓋）

---

## 5. 題型規格

### 5.1 MCQ
四選一。干擾項必須是**真實常見誤解**，例如「機會成本＝所有放棄選項之和」。自動判分。

### 5.2 填空配對（matching_fill）

```
把正確代號填入空格：
A 稀少性   B 機會成本   C 分工   D 競爭   E 生產要素

1. 由於資源不足以滿足所有慾望而須作出選擇，稱為 ____。
2. 在所放棄的選擇中價值最高的一項，稱為 ____。
```

逐格比對代號，錯格標紅並顯示正解。

### 5.3 短答（2–6 分）
答案存得分要點清單，逐點比對。格式：

> ① 指出稀少性為相對概念（1 分）② 解釋資源相對於慾望不足（1 分）③ 舉例（1 分）

### 5.4 長答（8–12 分）
只出題、計時、存文本。批改由我按 level-based marking 做，分數回填。

---

## 6. 批改規則

| 題型 | 判分者 | 說明 |
|---|---|---|
| MCQ | 機器 | 立即判、立即解析 |
| 填空配對 | 機器 | 逐格判 |
| 短答 | 機器初判＋我補 | 要點命中率 → 分數，我補講解 |
| 長答 | 我 | 插件只存不算 |

「以資料為準」的落地方式：每條要點可追溯 `chunk_id`，點開即見原文。

---

## 7. 範圍自動選擇

優先級：

```
1. 到期複習題（schedule.due_at <= today）
2. 未 mastered 的錯題考點
3. 最近入庫/最近學過的章節
4. 補足題數：已覆蓋考點平均抽
```

組卷後先顯示，用戶覺得不對可一句話改：

> **本次範圍**：機會成本(4)、稀少性(3)、分工(3)｜來源：課本 ch.1–2 ｜**跳過**：邊際分析（未覆蓋）

---

## 8. 真題策略（已確認可放）

1. 真題入庫時連 **marking scheme** 一併入庫 → 這是最可靠的「標準以資料為準」
2. 每題記 `seen: false`；用戶做過或看過答案的題改成 `seen: true`
3. **出題只抽 `seen: false` 的真題**，否則正確率統計失真
4. 真題常跨考點，`topics` 允許多對多
5. 版權：只作本地私人練習用，不再分發

---

## 9. 複習排程與曲線

### 9.1 錯題三階段

| 階段 | 時間 | 出題 |
|---|---|---|
| ① 原題重做 | 錯後 1 天 | 同一題 |
| ② 同考點變式 | 錯後 3 天 | 換情境/數字 |
| ③ 混合情境 | 錯後 7–21 天 | 與其他考點混考 |

答對兩次才 `mastered`，之後移出錯題本。

### 9.2 曲線三條

1. 首次作答正確率（真實水平）
2. 重做正確率（複習有效性）
3. **按考點正確率**（最有價值）

按週聚合，不按日。

## 10. 界面

```
┌─ 測驗 ──────────────┐
│ 範圍：見上             │
│ 題數：10  時間：40:00 │
│ [開始]                │
├──────────────────────┤
│ Q3/10  機會成本       │
│ 題幹……               │
│ ( ) A  ( ) B ( ) C   │
│ 出自：p.42            │
│ [下一題]              │
├──────────────────────┤
│ 今日收穫：掌握 3 個考點│
│ 錯題：2 條已入排程     │
└──────────────────────┘
```

- 每題固定顯示出處（`出自：p.42`）
- 結束頁給「今日收穫」，不只給分數

---

## 11. 不做清單

1. 不做連續打卡 streak（斷一天就整體放棄）
2. 不做長答自動打分
3. 不做無資料的自動擴題
4. 不做排行榜

---

## 12. 里程碑

| 階段 | 內容 | 備註 |
|---|---|---|
| v0 | 不裝插件，手工跑循環：入庫 → 出題 → 作答 → 批改 → 記錯 | 現在就能開始 |
| v1 | 本地腳本＋JSON 存儲，側邊欄可跑 MCQ／填空配對 | 約 2–3 小時 |
| v2 | 正式插件：SQLite、四題型、曲線、自動組卷 | 約 8–10 小時＋安裝調試 |

v0 要驗證兩件事：出題有沒跑偏、錯題回爐節奏受不受得了。這兩件事錯了 v1 白寫。
