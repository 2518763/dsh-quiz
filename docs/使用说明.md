# dsh-quiz 使用说明

面向使用者的操作手册。设计取舍见 [`设计稿-v2.md`](./设计稿-v2.md)。

---

## 0. 它是什么 / 不是什么

**是**：把你的课本原文变成可回查的题库，按 DSE 题型出题，错题按 1 天 / 3 天 / 14 天回炉，按考点算正确率。

**不是**：通用题库 App、刷题社区、自动批长答的机器。长答的分数由 AI 逐点给建议，你可以改。

---

## 1. 准备资料

插件只吃 **Markdown**，但你可以用三种方式把它喂进来：

| 你手上有 | 做法 |
|---|---|
| Markdown / 文本 | 直接给文件路径或粘贴原文 |
| 课本扫描 / 拍照 | 发图给 AI，让 AI 转成下面这种格式 |
| 手写笔记 | 同上，让 AI 转录 |

格式要求很简单：**frontmatter + 小节标题 + 页码**。

```markdown
---
book: 經濟學 中四上
edition: 2024 版
type: textbook
pages: 12-34
---

## 1.1 稀少性與選擇（p.12）

慾望無限而資源有限，這稱為稀少性。

## 1.2 機會成本（p.18）

在所放棄的選擇中，價值最高的一項稱為機會成本。
```

**页码一定要写**，因为它是「这道题出自哪一页」的唯一来源。写在标题里的 `（p.12）` 或 frontmatter 的 `pages: 12-34` 都行。

---

## 2. 导入

对 AI 说：

> 帮我把这份资料导入测验库，书名《經濟學 中四上》

对应工具 `quiz_import`。参数：

```json
{
  "book": "經濟學 中四上",
  "edition": "2024 版",
  "type": "textbook",
  "file": "C:/path/to/ch01.md"
}
```

返回 `chunks` 数量。**段落数是 0 就是没切出来**，多半是文件里没有 `##` 标题。

> 资料状态：`active` 可直接出题；如果内容来自 OCR、你还没校对，可以让 AI 先设 `status: "raw"`，校对后再改成 `reviewed`。

---

## 3. 建考点

考点是**统计与复习的单位**。名字自己定，但建议用课本的术语。

> 建两个考点：機會成本、稀少性

对应 `quiz_topics`（`action: "ensure"`）。别名可以顺手加：`opportunity cost`。

看覆盖：

> 看看现在哪些考点还没有题

对应 `quiz_topics`（`action: "coverage"`）：

```json
{
  "uncoveredTopics": ["分工"],
  "uncoveredChunks": 12,
  "totalChunks": 20
}
```

**这就是「未覆盖」的诚实输出**：有考点没题、有段落没出过题，都会列出来。

---

## 4. 出题

> 用「機會成本」这一段出两道题：一道选择、一道填空配对

对应 `quiz_add_question`。关键在 `answerPoints` —— **每个给分点都要带证据**：

```json
{
  "type": "mcq",
  "stem": "在所放棄的選擇中價值最高的一項稱為什麼？",
  "chunkIds": ["c_abc123"],
  "topicNames": ["機會成本"],
  "options": ["機會成本", "稀少性", "分工", "競爭"],
  "answerIndex": 0,
  "maxScore": 2,
  "answerPoints": [
    {
      "text": "機會成本的定義",
      "points": 2,
      "evidenceChunkId": "c_abc123",
      "quote": "在所放棄的選擇中，價值最高的一項稱為機會成本"
    }
  ]
}
```

`quote` 必须**能在原文里找到**（比对前会做空白与零宽字符归一化）。找不到 → 直接报错拒绝入库：

```
addQuestion: 给分点「…」的引文在 chunk c_abc123 里找不到。
```

这就是「无出处不出题」的执行点。**报错是对的**，不是 bug。

### 填空配对

```json
{
  "type": "matching_fill",
  "stem": "把正確代號填入空格",
  "chunkIds": ["c_abc123"],
  "topicNames": ["稀少性", "機會成本"],
  "maxScore": 4,
  "pairs": [
    { "prompt": "資源不足以滿足所有慾望，稱為 ___。", "code": "A" },
    { "prompt": "所放棄的選擇中價值最高的一項，稱為 ___。", "code": "B" }
  ]
}
```

### 短答 / 长答

`type: "short"` 或 `"long"`，不需要 options/pairs，但 `answerPoints` 里的每一点就是评分点。

## 5. 组卷

> 出 10 道题

对应 `quiz_start`。插件按这个配比自动挑：

| 来源 | 占比 |
|---|---|
| 到期复习 | 40% |
| 未掌握考点 | 30% |
| 最近学过的章节 | 20% |
| 混合迁移 | 10% |

返回里必看三项：

- `coverage`：这次考了哪些考点、哪本书哪几页
- `skipped`：为什么没凑满（题不够 / 某阶段没题）
- 每题 `whyNow`：**为什么这题现在出现**（到期复习 / 未掌握 / 新题）

模拟模式：

> 出一份模拟卷，10 题

`mode: "mock"` 时只出 `official` 或 `verified` 的题，**不会把答案交给 AI**，避免顺手说出去。

## 6. 作答与判分

| 题型 | 你答什么 | 谁判 |
|---|---|---|
| MCQ | 选项 | 机器 |
| 填空配对 | 每格的代号 | 机器（错一格即失败） |
| 短答 | 文字 | AI 逐点判 → 建议分 |
| 长答 | 文字 | AI 逐点 + level descriptor → 建议分 |

对应 `quiz_record`：

```json
{ "questionId": "q_...", "answer": { "choice": 1 }, "sessionId": "sess_..." }
```

返回会告诉你：

```json
{
  "passed": false,
  "verdictText": "答错，进入复习。",
  "scheduleNotes": ["答错，退回「原题重做」，明天再来。"],
  "items": [{ "stage": 1, "dueAt": "2026-10-22T...", "mastered": false }]
}
```

---

## 7. 复习节奏

```
错一次
  ↓ 第二天
stage 1：原题重做 ── 通过只算「恢复信号」
  ↓ 通过后 3 天
stage 2：同考点变式 ── 通过 = 证据一
  ↓ 通过后 14 天
stage 3：混合情境 ── 通过 = 证据二
  ↓
mastered
```

规则细节：

- **变式与混合阶段不能拿原题充数**，否则掌握判定失真（插件会拒绝并提示）
- 答错 → 退回上一阶段，明天再来
- 连续两次失败 → 进入「重新学习」，先看原文或解析再回池

## 8. 看统计

> 我现在的正确率怎么样？

`quiz_stats` 或打开 **设置 → 测验** 面板。

三条曲线**口径不同，不能互相替代**：

1. **首次正确率**：只算第一次见、且当时没看过答案的那一次。重做永远不进这条。
2. **分阶段重做**：1 天 / 3 天 / 14 天分开列。合成一条会掩盖「到底哪一步失效」。
3. **按考点**：多考点题按权重分摊，同一题不重复计数。

分母为 0 时显示 `—`，不是 `0%` —— **没有数据和正确率是 0 是两回事**。

## 9. 常见问题

**Q：导入后出不了题？**
A：看 `quiz_stats` / `coverage`。三种常见原因：资料状态是 `raw`、考点还没建、题还没入库。

**Q：题目状态 `draft` 是什么意思？**
A：AI 刚生成、还没验的题。练习模式可用，模拟模式不用。你做完、AI 批完且你没异议，会自动升 `verified`。

**Q：可以改 AI 给的分吗？**
A：可以。改过的记录会标 `userAdjusted`，并作为这一题的争议数据留下来——用于以后判断哪类题判得不准。

**Q：复习题堆积怎么办？**
A：每日到期上限 20 题，超出的顺延，不会一次塞爆。

**Q：数据能备份吗？**
A：整个 `.dsh-quiz/` 目录复制走就行，纯 JSON。
