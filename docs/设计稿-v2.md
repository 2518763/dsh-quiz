## 本版相對 v1 的變化

| # | 變化 | 原因 |
|---|---|---|
| 1 | 題目拆三級可信度：`official` / `verified` / `draft` | 綁 `chunk_id` 不等於題目正確 |

| 7 | 練習模式／模擬模式分開 | 出處與解析會洩題 |

## 0. 產品底線（四條）

1. **無出處不出題**：每題必須有 `question_chunks`，找不到原文就跳過並標「未覆蓋」。
2. **答案可回溯到原句**：每個評分點綁 `evidence_chunk_id` ＋ 可直接檢索的 `quote`。
3. **長答不冒充機判**：AI 給逐點證據與建議分，最終分可被用戶修改。
4. **爭議可記錄**：任何被用戶改過的判分，都進 `disputed` 佇列，不默默吞掉。

## 1. 佇列與模式

### 1.1 兩個佇列

| 佇列 | 可選題目 | 計不計入首次正確率 |
|---|---|---|
| 新題池 | 從未展示過的題（優先未做過的官方真題） | 計入 |
| 複習池 | 允許已見原題、變式題、混合題 | 不計入 |

### 1.2 題目曝光狀態（不再是單一布林 `seen`）

```
unseen     從未展示
shown      展示過但未作答
answered   已作答
revealed   看過答案或解析（此題永久不計入首次正確率）
repeated   已重複出現過
```

### 1.3 練習模式 vs 模擬模式

| | 練習模式 | 模擬模式 |
|---|---|---|
| 答題時看解析 | 可以 | 不可 |
| 顯示出處 | 顯示頁碼＋可展開原文 | **只顯示頁碼／章節** |
| 可選題目 | official／verified／draft | **只用 official＋verified** |
| 用途 | 當天學習、糾錯 | 算首次正確率、真實水平 |

模擬模式交卷後才開放原文與解析。

## 2. 掌握與排程

### 2.1 排程主體是「考點＋典型誤區」，不是單題

一個多考點題可拆出多個 `mastery_items`。以後複習優先換表述、換數字、換情境，避免記住選項位置。

### 2.2 三階段與 mastered 的真實條件

| 階段 | 時間 | 出什麼 | 成功算什麼 |
|---|---|---|---|
| stage 1 | 錯後 1 天 | 原題或近似題 | **恢復信號**，不算掌握 |
| stage 2 | 錯後 3 天 | 同考點變式（換情境/數字） | 證據一 |
| stage 3 | 錯後 7–21 天 | 混合情境 | 證據二 |

> **mastered = stage2 成功 ＋ stage3 成功，且兩者都不是原題。**

只重做同一道原題，不能證明會遷移。

### 2.3 失敗處理

- 答錯 → 退回上一階段，並提高下次優先級
- 連續兩次失敗 → 轉「重新學習」狀態：必須看原文或解析後才可回池
- 已 mastered 的考點 → 低頻抽檢，不進常規錯題佇列

### 2.4 答對的閾值（不同題型統一標準）

| 題型 | 「通過」的定義 |
|---|---|
| MCQ | 選項完全正確 |
| 填空配對 | **全部格子正確**；錯一格即進複習 |
| 短答 | `得分/滿分 ≥ 0.8` 且命中核心評分點 |
| 長答 | `得分/滿分 ≥ 0.7` 且核心 level descriptor 達標（閾值可調） |

## 3. 題目可信度

### 3.1 兩軸

```
origin_type    official | generated
review_status  draft | verified | disputed | rejected
```

| 狀態 | 含義 | 可否進模擬模式 |
|---|---|---|
| official | 真題、老師題、有官方 marking scheme | 可以 |
| verified | 生成題已通過校驗或無爭議批改 | 可以 |
| draft | 剛生成，未驗 | 只可練習模式，題面標「AI 生成」 |
| disputed | 有人對判分或題目提出異議 | 暫停使用 |
| rejected | 確認有錯 | 永不使用 |

### 3.2 自動升級（零額外操作）

```
draft →（用戶作答 → 批改 → 接受建議分）→ verified
draft →（用戶改分或提出異議）→ disputed →（覆核）→ verified / rejected
```

### 3.3 入庫校驗（生成時強制）

- [ ] `quote` 能在對應 `chunk` 中原文找到
- [ ] 題幹所需事實由證據支持
- [ ] 每個計分點都有 `evidence_chunk_id`
- [ ] 真題優先使用官方 marking scheme，不用模型重新解釋
- [ ] 多來源衝突時記錄採用了哪一份

## 4. 資料模型

```text
sources
  id, book, edition, type, pages, priority, status, content_hash, added_at
  -- priority: 1=marking scheme, 2=textbook, 3=notes
  -- status: raw | reviewed | active | archived

chunks
  id, source_id, heading, parent_heading, page_from, page_to, text, order

topics
  id, name, aliases[]

questions
  id, type, stem, max_score, difficulty, origin_type,
  review_status, active, created_at

question_topics        -- 多對多，帶權重
  question_id, topic_id, weight

question_chunks        -- 多對多
  question_id, chunk_id, purpose   -- purpose: stem | answer | distractor

answer_points          -- 批改核心，獨立存
  id, question_id, text, points, evidence_chunk_id, quote, sort_order

mastery_items
  id, topic_id, origin_question_id, stage(0-3),
  success_count, last_result, due_at, mastered_at, cooldown

attempts
  id, question_id, mode, answer, verdict, score, confidence,
  error_tags[], started_at, submitted_at
  -- mode: first | review | transfer | mock
```

`answer_points` 不再只是 JSON 思路，而是獨立表，可逐點追溯。

## 5. 批改

### 5.1 分層

| 題型 | 判分者 | 說明 |
|---|---|---|
| MCQ | 機器 | 立即判＋解析 |
| 填空配對 | 機器 | 逐格判，錯格標紅 |
| 短答 | AI 逐點判 → 建議分 → 可改 | 每點輸出「命中／部分／未中」＋證據 |
| 長答 | AI 逐點＋level descriptor → 建議分 → 可改 | 不產生不可更改的最終分 |

### 5.2 短答為什麼不做純關鍵詞

關鍵詞命中的問題：同義表達、否定句、因果關係、計算過程、關鍵詞出現在錯誤語境。所以用結構化 rubric，逐點判「命中程度」，並區分：

- **知識錯誤**（concept）
- **表達不完整**（expression）

### 5.3 錯誤歸因標籤

```
概念不清 / 記憶混淆 / 計算錯誤 / 看錯題意 / 時間不足 / 粗心 / 資料不足
```

AI 依作答自動建議 1–2 個標籤，用戶一鍵確認或改。

### 5.4 改分即爭議數據

- 用戶改分 → 該 attempt 記 `user_adjusted: true`
- 爭議率 = 被改分數 ÷ 總判分數，按題型統計
- 爭議率高的題型或考點，優先人工覆核

## 6. 組卷與每日上限

### 6.1 用戶可設

- 本次題數（預設 10）
- 模式（練習／模擬）

### 6.2 每日到期上限

- 到期任務預設上限 **20 題**，超出順延，不在下一次全塞回
- 用戶自訂題數優先，但只能從「已排定」的題裡選

### 6.3 組卷比例（顯式規則，不寫「優先」）

```
40%  到期複習
30%  未掌握考點
20%  最近學過的章節
10%  混合遷移題
```

範圍會先顯示給你確認：

> **本次範圍**：機會成本(4)、稀少性(3)、分工(3)｜來源：課本 ch.1–2｜**跳過**：邊際分析（未覆蓋）

## 7. 曲線口徑（三條互不混用）

### 7.1 首次作答正確率

只算：`mode = first` 且作答時題目狀態為 `unseen`。
重做過的原題、看過解析的題，永久不進這條。

### 7.2 重做正確率（按階段分開，不合成一條）

- stage 1 原題重做
- stage 2 變式
- stage 3 混合

合成一條會掩蓋「複習到底在哪一步失效」。

### 7.3 按考點正確率

- 多考點題按 `question_topics.weight` 分攤
- 同一次錯誤不重複計入每個考點
- 每個考點同時展示：首次正確率、複習後正確率、錯誤原因分布、最近一次錯誤時間

按週聚合，不按日。

## 8. 資料入庫

### 8.1 流程

1. 用戶發圖或檔案
2. AI 整理成結構化文本（保留章節、頁號、題號）
3. 存進 `sources/<slug>/chNN.md`
4. 建 chunk 索引
5. OCR 或手工轉錄的 chunk 先抽查一次，標 `reviewed` 後才開放出題

### 8.2 檔案格式

```markdown
---
book: 經濟學 中四上
edition: 2024 版
type: textbook
pages: 12-34
priority: 2
---

## 1.1 稀少性與選擇（p.12）

原文……

### 1.1.1 再說（p.13）

原文……
```

### 8.3 切段規則

- 按小節（`##`）切，保住前後文
- **單段上限約 1200 字**；超長則按小點（`###`）再切，但保留父標題與頁範圍
- 每段記 `page_from / page_to`

### 8.4 覆蓋面板（不只在結束頁）

```
已覆蓋考點        23
資料不足考點       4   ← 邊際分析、規模經濟……
最近新增無題段落   2
```

結束頁措辭用「答對／新增待複習／已鞏固」，**不用「今日掌握」**——當天答對不等於隔日記得。

## 10. 不做清單

1. 連續打卡 streak（斷一天就整體放棄）
2. 長答自動給不可更改的分
3. 無資料的自動擴題
4. 排行榜
5. 模擬模式中顯示原文或解析

## 11. v0 驗收標準（取代工時估算）

### 11.1 必須驗證的假設

1. 導入一章資料，生成 20–30 道題
2. 逐題核對題幹與要點是否真有原文支持
3. 標註至少 20 題，統計**題目跑偏率**與**批改爭議率**
4. 連續跑 10 次練習會話，確認範圍不失控
5. 同一考點跑完一次變式複習＋一次混合複習，確認 mastered 規則可執行
6. 確認未覆蓋考點一律顯示「未覆蓋」，不偷偷補題

### 11.2 通過標準

- 沒有無來源題目
- 沒有題目在原文找不到關鍵證據
- 錯題能正確進入下一階段排程
- 答錯可退回上一階段
- 用戶能看懂「為什麼這題現在出現」
- 題量增加後手動操作不明顯失控

通過後才做 SQLite、完整介面、圖表統計。
